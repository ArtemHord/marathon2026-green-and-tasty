## Що перевіряєш (`git diff main...HEAD` + незакомічені зміни)
1. **Специфікація:** кожне правило, код помилки й текст UI реалізовані; нічого зайвого, чого не просили.
2. **Авторизація:** хто може викликати кожен новий ендпоінт (Owner / customer бронювання / призначений офіціант); 401 без токена; немає шляху обійти перевірку через чужий id.
3. **Сумісність:** наявні поля відповідей не змінені й не видалені; відповідь `POST /group-reservations/{id}/submit` — як у `homework-backend.md`; тести `homework-tests/` не редагувались.
4. **Правило 3 місць** для нового ендпоінта: хендлер + `RouteRegistry.cs` + `deployment_resources.json` (`cognito_authorizer` там, де потрібен токен; `enable_cors`).
5. **Дані:** нові поля nullable; немає подвійних записів при гонці там, де це критично.
6. **Тести:** граничні значення й негативні сценарії є; ніхто не послабив і не видалив тест.
7. **Простота:** немає нових AWS-сервісів, бібліотек, абстракцій «на майбутнє». Найпростіше рішення, що виконує специфікацію.
8. **Секрети:** немає `.env`, `*.tfvars`, ключів, паролів, справжнього `backendUrl` у diff.
9. **Документація:** є `docs/features/<назва>.md` з розділами «Сценарій / Рішення / Що відкинули / Як перевірити / Обмеження».
